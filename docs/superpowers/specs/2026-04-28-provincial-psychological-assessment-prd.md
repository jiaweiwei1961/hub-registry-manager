## 1. Executive Summary (执行摘要)

我们正在为省级教育部门构建一个**智能心理量表普测平台**，面向全省200万中小学生，解决当前心理健康筛查工作分散、数据不统一、预警不及时的问题。该系统将提供一个统一的在线测评平台，支持可配置的量表库、自动化筛查预警、多维度数据分析报告，帮助各级教育管理者及时识别需要关注的学生并提供数据驱动的决策支持。

**核心目标：**
- 实现全省学生心理健康状况的年度普查，覆盖率目标 95%+
- 建立统一的筛查预警机制，预警识别准确率目标 90%+
- 提供省-市-区县-学校-班级五级数据分析报告，支撑教育决策
- 构建可持续运营的心理健康管理数字化基础设施

## 2. Problem Statement (问题陈述)

### 2.1 谁面临这个问题？

**主要利益相关者：**
- **省级教育厅**：需要掌握全省学生心理健康整体状况，制定政策
- **市级/区县教育局**：需要监控辖区内学校心理健康工作，识别重点问题
- **学校管理者**：需要了解本校学生心理健康状况，安排心理教育课程
- **班主任/心理教师**：需要识别班级内需要关注的学生，进行针对性辅导
- **学生**：需要便捷地完成心理测评，了解自己的心理状态

### 2.2 问题是什么？

当前中小学生心理健康筛查工作存在以下核心问题：

1. **工具不统一**：各地使用不同的心理量表，标准不一，数据无法横向对比
2. **流程分散**：测评工作依赖纸质问卷或零散系统，效率低下，容易出错
3. **预警滞后**：筛查结果统计周期长，无法及时发现和干预问题学生
4. **数据孤岛**：历史数据难以追溯，无法进行趋势分析和长期跟踪
5. **报告困难**：各级管理者难以快速获取所需的数据分析报告
6. **隐私风险**：学生心理数据敏感，缺乏统一的安全管理和权限控制

### 2.3 为什么这是个痛点？

**对学生的影响：**
- 无法及时发现心理问题，错过最佳干预时机
- 测评体验差，影响参与积极性

**对教育工作者的影响：**
- 班主任需要花费大量时间手动统计问卷结果
- 学校心理教师缺乏有效的筛查工具和工作流程
- 管理者无法及时获取决策所需的数据支撑

**对教育系统的影响：**
- 心理健康工作缺乏量化评估手段，难以考核
- 区域间数据无法对比，难以发现系统性问题
- 重大心理问题事件缺乏早期预警机制

### 2.4 证据支撑

- **政策要求**：《教育部关于加强学生心理健康管理工作的通知》要求每学年开展一次心理健康测评
- **现状调研**：某省试点调研显示，80%的学校仍使用纸质问卷，数据汇总需要 2-3 个月
- **问题数据**：中小学生心理问题检出率呈上升趋势，部分地区抑郁倾向检出率达 15-20%
- **案例**：某市因未能及时发现学生心理问题，导致极端事件发生，引发社会关注

## 3. Target Users & Personas (目标用户与角色)

### 3.1 主要角色

#### 角色 A: 省级管理员（省厅领导/心理健康负责人）

**档案：**
- **职位**：省教育厅心理健康教育负责人
- **年龄**：40-50 岁
- **技术能力**：中等，能使用办公软件和政务系统

**目标：**
- 掌握全省学生心理健康整体状况
- 识别心理健康问题高发区域和学校
- 制定针对性的心理健康教育政策
- 向上级汇报工作成效

**痛点：**
- 缺乏全省统一的数据视图
- 无法快速获取决策所需的统计报告
- 各地数据标准不一，难以汇总分析

**典型场景：**
> "每年需要向教育部汇报全省学生心理健康状况，目前需要各地市层层上报，数据汇总需要 1-2 个月，而且各地使用的量表不同，数据难以横向对比。"

#### 角色 B: 学校心理教师（一线心理健康工作者）

**档案：**
- **职位**：中学心理健康教师
- **工作量**：同时负责多班级的心理健康课程和咨询
- **技术能力**：中等，能熟练使用电脑和常用软件

**目标：**
- 高效完成全校学生的心理健康筛查
- 快速识别需要重点关注的学生
- 跟踪问题学生的状态变化
- 生成工作报告

**痛点：**
- 手工发放和回收问卷效率低下
- 手动统计得分容易出错
- 难以追踪学生的心理状态变化趋势
- 缺乏专业的预警和干预工具

**典型场景：**
> "每学期要对全校 2000 名学生进行心理健康测评，以前用纸质问卷，发卷、收卷、统计得分要花整整两周，还经常有漏填或错填的情况。"

#### 角色 C: 班主任（班级心理健康第一责任人）

**档案：**
- **职位**：初中班主任
- **班级规模**：45 名学生
- **工作负荷**：教学 + 班级管理 + 学生心理辅导

**目标：**
- 了解班级整体心理健康状况
- 识别班级内需要关注的学生
- 配合心理教师进行学生辅导
- 向家长反馈学生心理状况

**痛点：**
- 缺乏客观的学生心理健康数据支撑
- 难以区分"真正需要关注"和"偶发情绪波动"的学生
- 不知道如何与家长沟通学生心理问题

**典型场景：**
> "班上有学生最近情绪低落，但我不知道是学业压力还是家庭问题，如果有专业的测评数据作为参考，和家长沟通时会更有依据。"

#### 角色 D: 学生（测评参与者）

**档案：**
- **年龄**：12-18 岁
- **技术能力**：高，熟练使用智能手机和电脑
- **心理状态**：对心理测评可能存在抵触或好奇心理

**目标：**
- 便捷地完成测评任务
- 了解自己的心理状态
- 获得有用的心理健康建议

**痛点：**
- 测评时间过长，题目太多
- 担心隐私泄露，不敢真实作答
- 测评结果看不懂或没有反馈

**典型场景：**
> "学校让我们做心理问卷，几十页纸要写很久，而且不知道填完有什么用，也不知道会不会被老师和家长看到我的答案。"

## 4. Strategic Context (战略背景)

### 4.1 业务目标 (OKRs)

**Objective 1: 建立全省统一的心理健康测评体系**
- KR1: 完成全省 200 万学生的心理健康普查，覆盖率 ≥ 95%
- KR2: 建立统一的量表库，覆盖至少 5 种核心心理量表
- KR3: 实现省-市-区县-学校-班级五级数据贯通

**Objective 2: 提升心理健康筛查效率和效果**
- KR1: 单次测评完成时间从目前的平均 2 周缩短至 3 天内
- KR2: 预警识别准确率达到 90% 以上
- KR3: 问题学生从识别到干预的平均时间缩短至 1 周内

**Objective 3: 赋能各级心理健康教育工作**
- KR1: 90% 以上的学校通过系统生成心理健康工作报告
- KR2: 班主任/心理教师对系统满意度 ≥ 4.5/5
- KR3: 建立数据驱动的政策制定机制

### 4.2 市场机会

**TAM (总可寻址市场):**
- 全国中小学生约 1.9 亿人
- 按每学生年均测评 2 次，每次 5 元计算，市场规模约 19 亿元/年

**SAM (可服务市场):**
- 已建立心理健康测评制度的省市，约 5000 万学生
- 市场规模约 5 亿元/年

**SOM (可获得市场):**
- 目标省份 200 万学生
- 年测评服务收入约 2000 万元
- 系统建设 + 运维服务，合同金额约 800-1200 万元

### 4.3 竞争格局

| 竞争对手 | 优势 | 劣势 | 我们的差异化 |
|----------|------|------|--------------|
| 传统纸质测评 | 成本低、无需技术 | 效率低、易出错、难统计 | 数字化、自动化、实时分析 |
| 单一学校系统 | 针对性强 | 无法横向对比、难以推广 | 省级统一、标准化、可扩展 |
| 通用问卷工具（问卷星等） | 易用、成本低 | 缺乏专业量表、无预警机制 | 专业心理量表、智能预警、教育场景定制 |
| 医院心理测评系统 | 专业性强 | 面向个体、不适合大规模普查 | 面向群体、适合普查、教育管理视角 |

### 4.4 Why Now? (为什么是现在？)

**政策驱动：**
- 教育部 2021 年发布《关于加强学生心理健康管理工作的通知》，明确要求每学年开展一次心理健康测评
- 各省相继出台心理健康教育实施方案，要求建立筛查预警机制

**需求迫切：**
- 学生心理健康问题日益突出，极端事件频发，引发社会关注
- 传统测评方式效率低下，无法满足大规模普查需求

**技术成熟：**
- 云计算、大数据技术成熟，能够支撑百万级并发
- 心理测量学理论完善，量表信效度有保障
- 移动互联网普及，学生习惯在线答题

**先发优势：**
- 率先建立省级统一平台，形成数据积累和运营经验
- 可复制推广至其他省份，形成规模化效应

## 5. Solution Overview (解决方案概述)

### 5.1 解决方案描述

我们正在构建一个**省级智能心理量表普测平台**，为全省中小学生提供统一的在线心理健康测评服务。系统采用省-市-区县-学校-班级五级组织架构，支持可配置的专业心理量表库，实现从任务发布、在线答题、自动计分、智能预警到多维度报告生成的全流程数字化管理。

**核心工作流程：**

1. **量表配置**：省级管理员配置和管理心理量表库，设置计分规则和预警阈值
2. **任务发布**：各级管理员发布测评任务，选择测评对象和时间窗口
3. **学生答题**：学生通过 PC 或移动端在线答题，支持断网续答和进度保存
4. **自动计分**：系统自动计算量表得分，生成个体测评结果
5. **智能预警**：基于预设规则自动识别需要关注的学生，生成预警记录
6. **预警处置**：班主任和心理教师对预警学生进行跟进处置，记录处置过程
7. **报告生成**：自动生成个体、班级、学校、区域等多维度分析报告

**关键特性：**

- **可配置量表库**：支持 SCL-90、MHT、SDS、SAS 等多种专业量表，可灵活配置题目、维度、计分规则
- **五级组织架构**：省-市-区县-学校-班级五级管理，数据权限精准隔离
- **智能预警引擎**：基于规则的自动预警，支持总分预警、维度预警、综合预警等多种类型
- **多维度报告**：个体报告、班级报告、学校报告、区域报告，支持数据钻取和趋势分析
- **高并发支持**：支持峰值 3 万并发，日活 5 万，满足全省普查需求
- **数据安全**：符合《个人信息保护法》要求，数据加密存储，访问权限严格控制

### 5.2 用户流程

#### 流程 A: 省级管理员发布普查任务

```
登录系统 → 进入量表管理 → 选择/配置量表 → 创建测评任务
    ↓
设置测评时间 → 选择测评范围（全省/指定地市） → 发布任务
    ↓
监控进度 → 查看统计报告 → 导出数据
```

#### 流程 B: 学生完成测评

```
收到测评通知 → 登录系统 → 阅读测评说明 → 开始答题
    ↓
逐题作答（自动保存进度） → 答题完成 → 提交答卷
    ↓
查看结果（根据设置） → 退出系统
```

#### 流程 C: 班主任处理预警

```
收到预警通知 → 查看预警学生名单 → 查看学生测评详情
    ↓
进行学生访谈/观察 → 在系统中记录处置情况
    ↓
持续跟踪 → 评估效果 → 解除预警或升级处理
```

#### 流程 D: 心理教师生成报告

```
测评任务结束 → 进入报告管理 → 选择报告类型（班级/学校）
    ↓
设置报告参数 → 生成报告 → 预览报告内容
    ↓
导出 PDF → 打印或分享
```

| 模块 | 功能描述 | 目标用户 |
|------|----------|----------|
| **量表管理** | 量表库维护、题目配置、维度设置、计分规则、逻辑跳转 | 省级管理员 |

| **预警筛查** | 预警规则配置、实时计算、预警分级、处置跟踪 | 各级管理员/班主任 |
| **报告管理** | 个体/群体报告生成、PDF导出、报告分享、历史查询 | 所有用户 |

| **系统管理** | 系统配置、通知模板、审计日志、数据维护 | 省级管理员 |

### 5.4 系统架构（简要）

采用云原生微服务架构：
- **前端**：Vue3(管理端) + React(答题端)
- **后端**：Go/Java 微服务
- **数据库**：MySQL 分库分表 + Redis 缓存 + ClickHouse 分析库
- **基础设施**：Kubernetes + 阿里云/腾讯云

详细架构设计见技术规格文档。

## 6. Success Metrics (成功指标)

### 6.1 主要指标 (Primary Metrics)

**指标 1: 普查覆盖率**
- **定义**：实际参与测评学生数 / 应测学生总数 × 100%
- **当前基线**：无统一系统，各地差异大
- **目标值**：≥ 95%
- **衡量周期**：每学年度普查结束后统计

**指标 2: 测评完成率**
- **定义**：完成全部答题学生数 / 实际参与学生数 × 100%
- **当前基线**：约 85%（纸质问卷存在漏填、中途放弃）
- **目标值**：≥ 95%
- **衡量周期**：每次测评任务结束后统计

**指标 3: 预警识别准确率**
- **定义**：经人工复核确认需要关注的学生数 / 系统预警学生总数 × 100%
- **当前基线**：无统一标准，人工判断差异大
- **目标值**：≥ 90%
- **衡量周期**：抽样复核，每季度评估

| 指标 | 定义 | 当前值 | 目标值 | 说明 |

## 7. User Stories & Requirements (用户故事与需求)

### 7.1 Epic 假设

**Epic 1: 量表管理**
> 我们相信，提供一个可配置的量表管理系统，可以让省级管理员灵活维护心理测评工具，从而支持多样化的测评需求。我们将通过量表配置的灵活性和易用性来衡量成功。

> 我们相信，提供一个便捷的在线测评体验，可以提高学生的参与度和完成率，从而获得更准确的心理健康数据。我们将通过测评完成率和用户满意度来衡量成功。

**Epic 4: 数据分析报告**
> 我们相信，提供多维度的数据分析报告，可以帮助各级管理者科学决策，从而提升心理健康教育工作的针对性和效果。我们将通过报告使用率和决策支撑效果来衡量成功。

## 8. Out of Scope (范围外)

### 8.1 本次不实现的功能

| 功能 | 说明 | 原因 |
|------|------|------|
| **AI 智能诊断** | 基于 AI 的心理问题自动诊断 | 涉及医疗诊断，需要医疗资质，风险较高，暂不纳入 |
| **在线心理咨询** | 学生与咨询师在线实时沟通 | 需要专业咨询师资源和监管机制，二期考虑 |
| **家长端 APP** | 专门给家长使用的移动端应用 | 当前通过 H5 页面可满足需求，APP 开发成本高 |
| **智能推荐干预方案** | 基于测评结果推荐个性化干预方案 | 需要积累大量数据训练模型，二期优化 |
| **视频教程嵌入** | 量表中嵌入心理健康教育视频 | 增加系统复杂度和带宽压力，暂不优先 |
| **游戏化测评** | 将测评包装成游戏形式 | 需要专门的 UX 设计，当前优先保证功能完整性 |
| **第三方系统集成** | 与学籍系统、体检系统等外部系统集成 | 数据安全和接口协调复杂，当前保持独立系统 |
| **多语言支持** | 支持少数民族语言 | 当前服务范围内主要使用中文，二期考虑 |

### 10.2 待验证假设

- **假设 1**：学生愿意如实填写心理测评问卷
  - **验证方式**：试点阶段抽样访谈，分析答题时间分布和答案模式
  
- **假设 2**：班主任有足够精力跟进预警学生
  - **验证方式**：调研班主任日常工作量，了解预警学生数量和处置时间

- **假设 3**：在线测评结果与纸质测评结果一致性高
  - **验证方式**：对照实验，同一学生同时完成纸质和在线测评，对比得分

- **假设 4**：系统能够支撑峰值 3 万并发
  - **验证方式**：压力测试，模拟真实场景下的并发访问

| 普测 | Universal Screening | 面向大规模人群的普遍性测评 |
| 预警率 | Warning Rate | 预警学生数占总测评人数的比例 |
| 处置 | Disposition | 对预警学生进行跟进和干预的过程 |
| JTBD | Jobs-to-be-Done | 用户需要完成的任务或需要解决的问题 |
| RBAC | Role-Based Access Control | 基于角色的访问控制 |
