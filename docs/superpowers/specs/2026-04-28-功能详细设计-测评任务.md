## 3. 测评任务模块详细设计

### 3.1 测评任务生命周期

#### 3.1.1 任务状态流转图

```
                    ┌──────────────┐
                    │    草稿      │
                    │  (DRAFT)     │
                    └──────┬───────┘
                           │ 发布
                           ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   已暂停     │◀───│   待开始     │───▶│   进行中     │
│  (PAUSED)    │    │ (SCHEDULED)  │    │ (ONGOING)    │
└──────┬───────┘    └──────────────┘    └──────┬───────┘
       │                                        │
       │ 恢复                                   │ 到达截止时间
       └────────────────────────────────────────┘
                           │
                           ▼
                    ┌──────────────┐
                    │    已结束    │
                    │ (COMPLETED)  │
                    └──────┬───────┘
                           │ 归档
                           ▼
                    ┌──────────────┐
                    │    已归档    │
                    │ (ARCHIVED)   │
                    └──────────────┘
```

**状态定义与转换条件：**

| 状态 | 编码 | 说明 | 允许的操作 | 转换条件 |
|------|------|------|------------|----------|
| 草稿 | DRAFT | 任务正在创建中，未对外发布 | 编辑、删除、预览、发布 | 创建后初始状态 |
| 待开始 | SCHEDULED | 任务已发布，但未到开始时间 | 编辑（有限）、暂停、取消 | 发布且当前时间<开始时间 |
| 进行中 | ONGOING | 任务正在进行中，学生可答题 | 暂停、结束、监控 | 当前时间>=开始时间且<=结束时间 |
| 已暂停 | PAUSED | 任务被暂停，学生暂时无法答题 | 恢复、结束 | 管理员手动暂停 |
| 已结束 | COMPLETED | 任务已结束 | 查看结果、生成报告、重新开启 | 到达结束时间或管理员手动结束 |
| 已取消 | CANCELLED | 任务被取消 | 仅查看 | 管理员取消 |
| 已归档 | ARCHIVED | 任务数据已归档 | 仅查看历史 | 结束30天后自动归档 |

**状态转换详细规则：**

| 转换 | 触发条件 | 前置检查 | 系统行为 | 通知对象 |
|------|----------|----------|----------|----------|
| 草稿→待开始 | 点击"发布" | ①量表已选择 ②时间设置合理 ③对象已选择 | ①校验配置完整性 ②生成任务ID ③发送即将开始通知 | 相关管理员 |
| 待开始→进行中 | 到达开始时间 | - | ①自动状态变更 ②发送开始通知 ③开放答题入口 | 学生、班主任 |
| 进行中→已暂停 | 管理员点击"暂停" | 无正在进行的答题 | ①暂停答题入口 ②保存当前进度 ③发送暂停通知 | 学生、班主任 |
| 已暂停→进行中 | 管理员点击"恢复" | - | ①恢复答题入口 ②发送恢复通知 | 学生、班主任 |
| 进行中→已结束 | 到达结束时间 | - | ①自动提交未交卷 ②发送结束通知 ③触发计分 | 所有相关人员 |
| 进行中→已结束 | 管理员点击"结束" | - | 同上 | 同上 |
| 已结束→已归档 | 结束30天后 | - | ①归档历史数据 ②清理缓存 ③生成统计报告 | - |

### 3.2 测评任务业务规则

#### 3.2.1 时间规则

**时间冲突检测：**

```
同一学生同一时间只能有一个进行中任务
检测规则：
- 任务A的 [start_time, end_time] 与任务B的 [start_time, end_time] 重叠
- 且任务A和任务B的目标学生有交集
- 则判定为冲突
```

**冲突处理策略：**

| 冲突类型 | 处理方式 |
|----------|----------|
| 同一量表重复测评 | 提示"该学生已有相同量表的进行中的任务" |
| 不同量表时间重叠 | 允许，但提醒可能影响完成率 |
| 补测任务冲突 | 补测任务优先级高于普测任务 |

**时间变更规则：**

| 状态 | 允许变更 | 变更限制 |
|------|----------|----------|
| 草稿 | 全部可变更 | 无限制 |
| 待开始 | 部分可变更 | 开始时间必须大于当前时间 |
| 进行中 | 仅结束时间 | 只能延长，不能提前 |
| 已暂停 | 部分可变更 | 暂停期间时间不计入 |
| 已结束 | 不可变更 | 只能复制创建新任务 |

#### 3.2.2 对象选择规则

**层级级联规则：**

- 选择省级 → 自动包含其下所有市、区县、学校、班级
- 选择市级 → 自动包含其下所有区县、学校、班级
- 选择区县级 → 自动包含其下所有学校、班级
- 选择学校级 → 自动包含其下所有班级

**权限检查规则：**

```
创建任务时检查：
- 当前用户的数据权限范围是否包含所选择的测评对象
- 如：区县管理员不能选择其他区县的任务
- 如：学校管理员不能选择其他学校的班级

计算方式：
IF target_org_id IN user_permission_scope THEN allow
ELSE deny with error: "您没有权限为XX组织创建任务"
```

**学生动态变化处理：**

| 场景 | 处理规则 |
|------|----------|
| 任务发布后新入学学生 | 不自动加入，需手动添加或创建新任务 |
| 任务发布后转班学生 | 跟随学生，新班级可见该任务 |
| 任务发布后转出学生 | 保留答题权限，允许完成 |
| 任务发布后休学学生 | 自动移出任务名单 |
| 任务发布后复学学生 | 自动加入任务名单 |

#### 3.2.3 答题次数规则

**次数控制逻辑：**

```
IF max_attempts = 1:
    学生只能答题一次，提交后不可再答
    
IF max_attempts > 1:
    允许答题指定次数，每次重新开始
    取分方式根据 scoring_strategy:
        - last: 取最后一次得分
        - best: 取最高得分
        - average: 取平均分
        - first: 取第一次得分
```

**答题记录追踪：**

| 字段 | 说明 |
|------|------|
| 尝试次数 | 第几次答题（1, 2, 3...） |
| 是否有效 | 该次答题是否计入结果 |
| 开始时间 | 该次答题开始时间 |
| 提交时间 | 该次答题提交时间 |
| 答题时长 | 该次答题用时 |
| 得分 | 该次答题得分 |
| 状态 | completed/abandoned/in_progress |

#### 3.3.3 催答功能

**催答条件：**

- 任务进行中
- 距离结束时间小于 48 小时
- 学生状态为"未开始"或"进行中但未完成"

**催答方式：**

| 方式 | 内容 | 发送时间 |
|------|------|----------|
| 系统消息 | 站内信通知 | 即时 |
| 短信通知 | "您有未完成的心理测评任务，请尽快登录系统完成。截止时间是XX。" | 每日14:00统一发送 |
| 邮件通知 | 详细任务说明和链接 | 首次催答发送 |

**催答记录：**

| 字段 | 说明 |
|------|------|
| 催答时间 | 发送催答的时间 |
| 催答方式 | 系统消息/短信/邮件 |
| 催答对象数 | 本次催答的学生数量 |
| 催答人 | 发起催答的管理员 |
| 响应率 | 催答后完成的比例 |

### 3.4 补测管理

#### 3.4.1 补测场景

| 场景 | 判定条件 | 处理方式 |
|------|----------|----------|
| 缺测 | 任务结束时状态为"未开始" | 标记为缺测，可安排补测 |
| 答题无效 | 答题时间 < 最短有效时间 | 标记为无效，需重测 |
| 异常退出 | 答题过程中断后未恢复 | 标记为异常，可补测 |
| 系统故障 | 提交时发生系统错误 | 自动标记，自动补测资格 |
| 请假缺测 | 因请假未参与 | 手动标记，可安排补测 |

#### 3.4.2 补测流程

```
1. 识别补测名单（系统自动+手动添加）
2. 创建补测任务（或加入现有任务补测名单）
3. 设置补测时间窗口
4. 发送补测通知
5. 学生完成补测
6. 补测结果标记为"补测"
7. 合并到原任务统计（可选）
```

**补测任务配置：**

| 配置项 | 说明 |
|--------|------|
| 补测对象 | 从缺测名单中选取 |
| 使用量表 | 通常与原任务相同 |
| 时间窗口 | 通常比原任务短，3-7天 |
| 次数限制 | 通常只允许1次 |
| 结果合并 | 是否用补测结果替换原结果 |
