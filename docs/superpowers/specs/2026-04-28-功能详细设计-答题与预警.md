## 4. 学生答题模块详细设计

### 4.1 答题流程状态机

#### 4.1.1 学生答题状态流转

```
┌──────────────┐    开始答题      ┌──────────────┐
│   未开始     │ ──────────────▶ │   进行中     │
│ (NOT_START) │                  │ (IN_PROGRESS)│
└──────────────┘                └──────┬───────┘
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         │                             │                             │
         │ 中断答题                    │ 完成答题                    │ 提交答卷
         │ (interrupt)                 │ (complete)                  │ (submit)
         │                             │                             │
         ▼                             ▼                             ▼
┌──────────────┐                ┌──────────────┐                ┌──────────────┐
│   已中断     │                │  答题完成    │                │   已提交     │
│(INTERRUPTED) │                │ (COMPLETED)  │                │ (SUBMITTED)  │
└──────┬───────┘                └──────┬───────┘                └──────┬───────┘
       │                               │                             │
       │ 恢复答题                      │ 提交答卷                    │ 计分完成
       │ (resume)                      │                             │
       └───────────────────────────────┘                             ▼
                                                           ┌──────────────┐
                                                           │   已计分     │
                                                           │  (SCORED)    │
                                                           └──────┬───────┘
                                                                  │
                                                                  │ 生成结果
                                                                  │
                                                                  ▼
                                                           ┌──────────────┐
                                                           │   已完成     │
                                                           │ (FINISHED)   │
                                                           └──────────────┘
```

**状态定义：**

| 状态 | 编码 | 说明 | 触发条件 | 可执行操作 |
|------|------|------|----------|------------|
| 未开始 | NOT_START | 学生可以看到任务但未开始答题 | 任务已发布，学生被包含在目标范围内 | 开始答题、查看任务说明 |
| 进行中 | IN_PROGRESS | 学生正在答题 | 点击"开始答题" | 作答、保存进度、中断、提交 |
| 已中断 | INTERRUPTED | 学生中途退出但保留进度 | 关闭页面或点击"保存并退出" | 恢复答题、放弃答题 |
| 答题完成 | COMPLETED | 学生答完所有题目但未提交 | 答完最后一题 | 提交答卷、返回检查 |
| 已提交 | SUBMITTED | 学生已提交答卷，等待计分 | 点击"提交答卷" | 等待计分结果 |
| 已计分 | SCORED | 系统已完成计分 | 计分完成 | 查看结果（如允许） |
| 已完成 | FINISHED | 答题流程结束 | 结果生成完成 | 查看结果、历史记录 |
| 已过期 | EXPIRED | 超过截止时间 | 到达任务结束时间 | 仅可查看（如允许） |
| 已作废 | INVALIDATED | 答题被标记为无效 | 异常检测或人工标记 | 查看作废原因 |

#### 4.1.2 状态转换详细规则

| 转换 | 触发条件 | 前置检查 | 系统行为 | 数据操作 |
|------|----------|----------|----------|----------|
| 未开始→进行中 | 学生点击"开始答题" | ①任务状态为进行中 ②学生未被禁用 ③未达答题次数上限 | ①记录开始时间 ②初始化答题会话 ③加载题目 | 创建答题记录(answer_id)，状态=IN_PROGRESS |
| 进行中→已中断 | 学生关闭页面或点击"保存并退出" | - | ①保存当前答题进度到Redis ②记录中断时间 | 更新answer记录，保存当前进度快照 |
| 已中断→进行中 | 学生重新进入答题页面 | ①Redis中仍有有效进度 ②未超过中断保留时长 | ①从Redis恢复进度 ②加载已答题目 | 读取Redis恢复答题状态 |
| 进行中→答题完成 | 学生答完最后一题 | 所有必填题目已回答 | ①标记答题完成 ②进入提交前预览 | 更新状态=COMPLETED |
| 答题完成→已提交 | 学生点击"提交答卷" | - | ①提交答卷数据 ②触发计分流程 | 更新状态=SUBMITTED，发送计分消息 |
| 进行中→已提交 | 到达截止时间自动提交 | - | ①自动提交已答题目 ②标记为超时提交 | 更新状态=SUBMITTED，标记timeout_submit=true |
| 已提交→已计分 | 计分服务完成计分 | 计分成功 | 生成得分数据 | 创建/更新result记录，状态=SCORED |
| 已计分→已完成 | 结果生成完成 | - | 完成整个流程 | 更新状态=FINISHED |
| 进行中→已过期 | 到达任务结束时间 | - | 尝试自动提交，如失败则标记过期 | 状态变更为EXPIRED |

### 4.4 自动保存机制

#### 4.4.1 保存触发条件

| 触发场景 | 触发条件 | 保存内容 | 保存目标 |
|----------|----------|----------|----------|
| 定时自动保存 | 每30秒 | 当前页面答案 + 进度 | Redis + LocalStorage |
| 题目切换保存 | 点击"下一题"或"上一题" | 当前题答案 | Redis + LocalStorage + DB（异步） |
| 手动保存 | 点击"保存并退出" | 全部答案 + 进度 | Redis + LocalStorage + DB |
| 页面关闭保存 | beforeunload 事件 | 当前状态 | LocalStorage |
| 网络恢复保存 | 检测到网络恢复 | 离线期间答案队列 | Redis + DB |
| 异常中断保存 | 检测到异常（崩溃等） | 最后已知状态 | LocalStorage（备份） |

#### 4.4.2 保存数据优先级

```
保存优先级（高到低）：
1. LocalStorage (L1) - 即时本地备份
2. Redis (L2) - 分布式缓存
3. Database (L3) - 持久化存储

写入顺序：LocalStorage → Redis → Database
读取顺序：Redis → LocalStorage → Database（逐级回退）
```

### 4.5 异常检测与处理

#### 4.5.1 异常检测规则

| 异常类型 | 检测规则 | 阈值 | 处理动作 |
|----------|----------|------|----------|
| 答题过快 | 总用时 / 题目数 < 阈值 | < 3秒/题 | 标记异常，提示确认 |
| 答题过慢 | 单题用时 > 阈值 | > 600秒/题 | 提醒继续，超时自动保存 |
| 答案模式异常 | 连续N题选择相同选项 | >= 10题 | 标记异常，人工复核 |
| 中途长时间停留 | 当前题无操作时间 > 阈值 | > 300秒 | 弹窗确认是否继续 |
| 多设备登录 | 同一账号在多个设备答题 | 2+设备 | 踢出先前会话，保留最新 |
| 答案修改频率 | 反复修改同一题答案 | >= 5次 | 记录，不阻断 |
| 异常时间段 | 凌晨等非正常时段答题 | 22:00-06:00 | 记录，正常处理 |
| IP地址异常 | IP归属地与学校不符 | - | 记录，人工复核 |

#### 4.5.2 异常处理流程

**答题过快处理：**

```
1. 系统检测到答题速度异常
2. 弹窗提示："检测到您的答题速度较快，请确认是否认真作答？"
3. 选项："重新检查" / "继续提交"
4. 如选择"重新检查"，返回答题页面
5. 如选择"继续提交"，记录异常标记，继续流程
6. 异常标记随答卷一起提交，用于后续人工复核
```

**多设备登录处理：**

```
设备A正在答题 ──设备B登录──▶ 设备A收到通知
                                  │
                                  ▼
                          ┌──────────────┐
                          │ 会话冲突提示  │
                          │ "您的账号已在 │
                          │  其他设备登录  │
                          │  是否继续？" │
                          └──────────────┘
                                  │
                    ┌─────────────┴─────────────┐
                    ▼                           ▼
              选择"继续"                    选择"退出"
                    │                           │
                    ▼                           ▼
            设备A继续答题              设备A保存并退出
            设备B被踢出                设备B继续答题
```

#### 5.1.2 条件配置详细

**条件类型 1: 总分预警 (score)**

```json
{
  "rule_type": "score",
  "condition": {
    "operator": "greater_than_or_equal",
    "value": 60,
    "scale_id": "scale_xxx"
  },
  "description": "总分大于等于60分触发预警"
}
```

**条件类型 2: 维度预警 (dimension)**

```json
{
  "rule_type": "dimension",
  "condition": {
    "dimension_id": "dim_anxiety",
    "operator": "greater_than_or_equal",
    "value": 20,
    "scale_id": "scale_xxx"
  },
  "description": "焦虑维度得分大于等于20分触发预警"
}
```

**条件类型 3: 综合预警 (composite)**

```json
{
  "rule_type": "composite",
  "condition": {
    "operator": "AND",
    "conditions": [
      {
        "operator": "OR",
        "conditions": [
          {
            "type": "score",
            "operator": "greater_than_or_equal",
            "value": 50
          },
          {
            "type": "dimension",
            "dimension_id": "dim_depression",
            "operator": "greater_than_or_equal",
            "value": 15
          }
        ]
      },
      {
        "type": "dimension",
        "dimension_id": "dim_anxiety",
        "operator": "greater_than_or_equal",
        "value": 15
      }
    ]
  },
  "description": "(总分>=50 或 抑郁维度>=15) 且 焦虑维度>=15"
}
```

**条件类型 4: 异常答题预警 (abnormal)**

```json
{
  "rule_type": "abnormal",
  "condition": {
    "abnormal_type": "answer_too_fast",
    "threshold": 3,
    "unit": "seconds_per_question"
  },
  "description": "答题速度过快，平均少于3秒每题"
}
```

支持异常类型：
- `answer_too_fast`: 答题过快
- `answer_too_slow`: 答题过慢
- `answer_pattern_suspicious`: 答题模式可疑（如连续相同选项）
- `multi_device_login`: 多设备登录
- `incomplete_answer`: 答题不完整（跳题过多）

**条件类型 5: 趋势预警 (trend)**

```json
{
  "rule_type": "trend",
  "condition": {
    "compare_with": "previous",
    "metric": "total_score",
    "operator": "increased_by",
    "value": 20,
    "unit": "percentage"
  },
  "description": "与上次测评相比，总分上升超过20%"
}
```

#### 5.1.3 规则优先级与冲突处理

**优先级规则：**

1. **按规则优先级字段**：priority 值越小优先级越高
2. **按预警级别**：severe > moderate > mild
3. **按规则类型**：trend > abnormal > composite > dimension > score
4. **按创建时间**：新规则 > 旧规则

**冲突处理策略：**

| 场景 | 处理策略 |
|------|----------|
| 同一学生触发多条规则 | 保留预警级别最高的那条 |
| 多条规则生成同一级别预警 | 合并预警记录，记录所有触发规则 |
| 同一维度多个规则触发 | 取最严重的预警级别 |
| 总分预警和维度预警同时触发 | 分别记录，显示所有触发原因 |

### 5.4 预警处置流程

#### 5.4.1 处置状态流转

```
待处置 ──▶ 处置中 ──▶ 已处置
   │          │
   │          ▼
   │       转介中 ──▶ 转介完成
   │
   ▼
已关闭（误报/无需处置）
```

**状态定义：**

| 状态 | 说明 | 可执行操作 |
|------|------|------------|
| 待处置 (pending) | 预警刚生成，等待首次处置 | 开始处置、标记误报、关闭 |
| 处置中 (in_progress) | 正在进行干预措施 | 添加处置记录、转介、完成处置 |
| 转介中 (referring) | 已转介给专业机构/人员 | 更新转介状态、转介完成 |
| 转介完成 (referral_completed) | 转介流程结束 | 查看转介结果、继续跟踪 |
| 已处置 (resolved) | 处置措施已完成 | 查看处置记录、重新开启 |
| 已关闭 (closed) | 预警已关闭（误报或无需处置） | 查看记录、重新开启 |

#### 5.4.2 处置记录详细

**处置记录表字段：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| 记录ID | String | 系统生成 | UUID |

#### 5.4.3 转介流程

```

4. 区县管理员审批（如需要）
5. 联系转介机构
6. 家长知情同意（必须）
7. 学生转介
8. 跟踪转介结果
9. 更新预警状态
```
