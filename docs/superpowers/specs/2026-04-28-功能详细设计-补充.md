## 1. 量表管理模块详细设计

### 1.1 量表生命周期管理

#### 1.1.1 量表状态流转

```
草稿 ──发布──▶ 已发布 ──下架──▶ 已下架
 │                        │
 │                        │
 └──编辑──▶ 草稿          └──重新发布──▶ 已发布
 │
 └──删除（仅限无使用记录的草稿）
```

**状态定义：**

| 状态 | 说明 | 可执行操作 |
|------|------|------------|
| 草稿 | 量表正在创建或编辑中，未对外可见 | 编辑、删除、发布、预览 |
| 已发布 | 量表已发布，可用于创建测评任务 | 查看、复制、创建新版本、下架、预览 |
| 已下架 | 量表已下架，新任务不能使用，但历史任务不受影响 | 查看、复制、重新发布、删除（无任务关联时） |

**状态流转规则：**

| 流转 | 触发条件 | 系统行为 | 前置检查 |
|------|----------|----------|----------|
| 草稿 → 已发布 | 管理员点击"发布" | 校验量表完整性，生成版本号，记录发布时间 | ①题目数>0 ②维度已配置 ③计分规则完整 |
| 已发布 → 已下架 | 管理员点击"下架" | 标记下架时间，禁止新任务使用 | 无在用任务依赖 |
| 已下架 → 已发布 | 管理员点击"重新发布" | 恢复可用状态 | 量表内容完整性检查 |
| 草稿 → 已删除 | 管理员点击"删除" | 物理删除或逻辑删除 | 无历史任务关联 |

#### 1.3.2 计分方式详解

**方式 1: 累加计分 (sum)**

```
维度得分 = Σ(各题目得分)
```

适用场景：各题目对维度贡献相同，如SCL-90的各维度。

**方式 2: 平均计分 (average)**

```
维度得分 = Σ(各题目得分) / 题目数量
```

适用场景：维度题目数量不同时，需要标准化比较。

**方式 3: 加权计分 (weighted)**

```
维度得分 = Σ(各题目得分 × 对应权重) / Σ(权重)
```

适用场景：不同题目对维度重要性不同。

**配置示例：**

```json
{
  "scoring_method": "weighted",
  "weights": {
    "q_001": 1.0,
    "q_002": 1.5,
    "q_003": 1.0,
    "q_004": 2.0
  }
}
```

**方式 4: 自定义计分 (custom)**

支持通过公式表达式定义计分逻辑。

```
dimension_score = IF(sum_score > 50, sum_score * 1.2, sum_score)
```

支持的操作符：+、-、*、/、^、>、<、>=、<=、==、!=、&&、||、IF、MIN、MAX、AVG

### 1.4 量表版本管理

#### 1.4.1 版本管理策略

采用语义化版本控制（SemVer）：`主版本.次版本.修订号`

| 版本变化 | 触发场景 | 示例 |
|----------|----------|------|
| 主版本+1 | 重大变更，不兼容旧版本 | 量表结构重大调整，1.x.x → 2.0.0 |
| 次版本+1 | 新增功能，向后兼容 | 新增维度或题目，1.1.x → 1.2.0 |
| 修订号+1 | 问题修复，向后兼容 | 题目描述修正，1.1.1 → 1.1.2 |

#### 1.4.2 版本对比功能

**对比维度：**

| 对比项 | 说明 |
|--------|------|
| 基础信息 | 名称、说明、时长等字段变化 |
| 题目变更 | 新增、删除、修改的题目 |
| 选项变更 | 选项内容、分值的变化 |
| 维度变更 | 维度定义、关联题目的变化 |
| 计分规则 | 计分方式、等级划分的变化 |
| 逻辑跳转 | 跳转规则的变化 |

**对比展示：**

- 左侧：版本A内容
- 右侧：版本B内容
- 中间：差异高亮（绿色=新增，红色=删除，黄色=修改）

#### 2.2.4 数据权限规则

**数据可见性规则：**

```sql
-- 查询某用户可见的学生数据
WHERE school_id IN (
    SELECT school_id FROM user_permission_scope 
    WHERE user_id = :current_user_id
)

-- 查询某用户可见的班级数据  
WHERE class_id IN (
    SELECT class_id FROM user_permission_scope 
    WHERE user_id = :current_user_id
)

-- 预警数据特殊权限（仅能看到自己层级的预警）
WHERE warning_level_scope <= :user_max_warning_level 
AND school_id IN (用户管辖学校)
```

**权限层级继承：**

- 省级管理员可查看全省数据
- 市级管理员可查看本市及下辖区县、学校数据
- 区县管理员可查看本区县及下辖学校数据
- 学校管理员可查看本校及下辖班级数据
- 班主任仅可查看本班数据
- 学生仅可查看个人数据

**特殊权限规则：**

| 场景 | 规则 |
|------|------|
| 预警学生详情 | 班主任只能看到本班预警学生，心理教师可看到本校预警学生，学校管理员可看到全校预警学生 |
| 预警名单导出 | 需要审批，区县以上级别管理员可审批 |
| 敏感操作（如删除学生） | 需要二次确认和操作理由 |
| 跨级查看 | 需上级授权，并记录审计日志 |

### 2.3 学生异动管理

#### 2.3.1 异动类型

| 异动类型 | 编码 | 说明 | 影响范围 |
|----------|------|------|----------|
| 转入 | TRANSFER_IN | 从外校转入 | 新增学生记录，关联新班级 |
| 转出 | TRANSFER_OUT | 转到外校 | 标记转出状态，保留历史数据 |
| 转班 | CLASS_CHANGE | 校内班级调整 | 更新班级关联，记录异动历史 |
| 休学 | SUSPENSION | 暂停学业 | 标记休学状态，暂停参与测评 |
| 复学 | RESUMPTION | 休学后恢复 | 恢复在读状态 |
| 退学 | DROPOUT | 退学 | 标记退学状态 |
| 毕业 | GRADUATION | 正常毕业 | 标记毕业状态，归档数据 |
| 升级 | PROMOTION | 年级升级 | 批量更新年级和班级 |

#### 2.3.2 异动流程

**转入流程：**

```
1. 接收转入申请（含原学校证明、学籍信息）
2. 校验学生身份（身份证号）
3. 创建学生档案
4. 分配班级
5. 通知班主任
6. 同步历史测评数据（从省平台查询）
```

**转出流程：**

```
1. 提交转出申请
2. 确认无在办预警（需处理完成）
3. 标记转出状态
4. 生成学籍档案转出包
5. 30天后归档数据
```

**转班流程：**

```
1. 提交转班申请（原班主任/学校管理员）
2. 目标班级班主任确认
3. 学校管理员审批
4. 更新班级关联
5. 通知相关班主任
6. 预警记录跟随转移
```
