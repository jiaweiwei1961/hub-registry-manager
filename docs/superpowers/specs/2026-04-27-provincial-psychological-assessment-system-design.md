# 省级智能心理量表普测系统设计文档

> 创建日期: 2026-04-27

---

## 一、系统概述

### 1.1 系统定位

省级智能心理量表普测平台，面向全省200万中小学生，提供可配置量表库、在线答题、筛查预警、多维度报告分析功能。采用五级组织架构（省-市-区县-学校-班级），支持分散时段答题，日活5万，峰值3万并发。

### 1.2 核心业务流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  量表配置   │───▶│  测评任务   │───▶│  学生答题   │
│ (省/市管理) │    │   发布      │    │ (分散时段)  │
└─────────────┘    └─────────────┘    └─────────────┘
                                             │
                                             ▼
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  预警处置   │◀───│  筛查分析   │◀───│  数据采集   │
│ (干预跟踪)  │    │ (规则引擎)  │    │ (实时计算)  │
└─────────────┘    └─────────────┘    └─────────────┘
       │
       ▼
┌─────────────┐
│  报告生成   │
│ (多维度)    │
└─────────────┘
```

### 1.3 主要用户角色

| 角色 | 职责范围 | 核心功能 |
|------|----------|----------|
| 省级管理员 | 全省数据 | 量表库管理、全省数据查看、省级报告 |
| 市/区县管理员 | 辖区数据 | 测评任务发布、数据查看、辖区报告 |
| 学校管理员 | 本校数据 | 测评组织、学生管理、学校报告 |
| 班主任 | 本班数据 | 答题监控、预警查看、班级报告 |
| 学生 | 个人数据 | 在线答题、查看个人报告 |

### 3.2 核心数据模型

```
Province(省) → City(市) → District(区县) → School(学校) → Class(班级) → Student(学生)

WarningRule(预警规则) → Warning(预警记录)
Report(报告)
```


## 四、高并发与性能设计

### 4.1 并发流量处理链路

| Layer | 组件 | 处理能力 |
|-------|------|----------|
| Layer 1 | DNS + CDN | 静态资源加速、就近接入 |
| Layer 2 | Nginx Ingress + Sentinel | 限流5万QPS、熔断降级 |
| Layer 3 | K8s HPA | 自动扩缩容（CPU>60%扩容） |
| Layer 4 | Redis + MySQL读写分离 | 缓存预热、连接池控制 |

### 4.2 核心场景性能指标

| 场景 | 优化策略 | 目标指标 |
|------|----------|----------|
| 进入答题页 | 量表题目Redis预加载 | RT < 100ms |
| 答题提交 | 异步队列+本地缓存暂存 | RT < 50ms |
| 题目翻页 | 预加载下一页+本地缓存 | RT < 30ms |
| 实时统计 | Redis计数器+ClickHouse | RT < 200ms |
| 报告查询 | OSS CDN+预生成缓存 | RT < 500ms |

### 4.3 答题流程优化

1. **进入答题**：量表题目全量加载到浏览器本地存储，答题进度实时保存到Redis
2. **答题过程**：本地答题无网络交互，每5题或每30秒自动保存到Redis
3. **提交答卷**：本地数据打包提交，入消息队列异步处理，立即返回成功
4. **结果查询**：结果计算完成后通知用户，支持稍后主动查询

### 4.4 缓存分层策略

| 层级 | 存储 | 内容 | 有效期 |
|------|------|------|--------|
| L1 | 浏览器LocalStorage | 量表题目、答题进度 | 答题期间 |
| L2 | Redis | 量表定义、Session、答题进度、统计计数器 | 7天~永久 |
| L3 | ClickHouse物化视图 | 预计算统计报表 | 按天/周/月 |

## 五、安全与合规设计

### 5.1 安全分层架构

| Layer | 安全措施 |
|-------|----------|
| 网络安全 | HTTPS全站加密、WAF防护、DDoS防护、VPC网络隔离 |
| 应用安全 | JWT认证、RBAC权限控制、API签名验证、参数校验 |
| 数据安全 | 密码BCrypt加密、敏感数据脱敏、数据库字段AES-256加密 |
| 运维安全 | 操作日志审计、登录审计、数据访问审计、KMS密钥管理 |

### 5.2 五级数据权限隔离

| 角色 | 数据范围 | 操作权限 |
|------|----------|----------|
| 省级管理员 | 全省数据 | 查看/导出/量表配置/预警管理 |
| 市级管理员 | 本市数据 | 查看/导出/任务发布/预警处理 |
| 区县管理员 | 本区县数据 | 查看/导出/任务发布/预警处理 |
| 学校管理员 | 本校数据 | 查看/导出/学生管理/预警跟进 |
| 班主任 | 本班数据 | 查看/预警跟进/班级报告 |
| 学生 | 个人数据 | 答题/查看个人报告 |

权限校验方式：
- SQL层面：WHERE school_id IN (用户管辖学校列表)
- API层面：数据返回前过滤
- 缓存层面：Redis存储用户权限范围

### 5.3 预警数据隐私保护

**数据分级：**
- 普通数据：班级以上级别可查看汇总
- 预警数据：仅班主任+学校心理教师可见具体学生
- 严重预警：学校+区县可见，需审批查看详情

**展示脱敏：**
- 报告中姓名脱敏（如"张*"）
- 导出数据时预警学生信息加密
- 历史数据中预警信息自动脱敏

**操作审批：**
- 查看预警学生详情需学校管理员授权
- 导出预警数据需区县管理员审批
- 删除预警记录需市级管理员审批

### 5.4 合规审计日志

**审计事件：**
- 用户登录/退出
- 数据查询（学生信息、测评结果、预警信息）
- 数据导出操作
- 权限变更操作
- 预警处置操作
- 量表配置变更
- 测评任务发布

**日志存储：**
- Elasticsearch集群存储
- 保留周期：3年
- 不可篡改：只允许写入

## 六、报告与分析模块

### 6.1 报告类型体系

**一、个体报告**
- 学生测评报告：量表得分、维度分析、预警等级
- 个人历史报告：多次测评趋势对比
- 导出格式：PDF（加密）、在线查看

**二、群体报告**
- 班级报告：班级整体情况、分布统计、预警名单
- 学校报告：各年级对比、全校汇总、重点班级
- 区县报告：各学校对比、区域汇总、重点学校
- 市级报告：各区县对比、全市汇总、重点区域
- 省级报告：各市对比、全省汇总、重点城市

**三、专项分析报告**
- 预警分析报告：预警分布、类型统计、处置情况
- 趋势对比报告：年度对比、学期对比
- 横向对比报告：同级别区域/学校横向对比
- 干预效果报告：预警学生前后测评对比

### 6.2 学生个体报告结构

| Part | 内容 |
|------|------|
| Part 1 | 基本信息：学生信息（脱敏）、测评时间、量表名称 |
| Part 2 | 量表得分：总分及等级评定、各维度得分及解读、图表展示 |
| Part 3 | 预警信息（如有）：预警等级及类型、预警维度说明、建议关注事项 |
| Part 4 | 历史趋势（多次测评）：各维度变化趋势图、与上次测评对比 |
| Part 5 | 说明与建议：量表说明、结果解读注意事项、心理健康建议 |

### 6.3 群体统计分析维度

**一、基础统计**
- 测评完成率：应测人数 vs 实测人数
- 分数分布：正态分布图、分段统计
- 维度得分：各维度平均值、标准差
- 性别对比：男女学生差异分析
- 年级对比：各年级得分分布

**二、预警统计**
- 预警率：预警人数占比
- 预警类型分布：各类预警人数统计
- 预警级别分布：轻度/中度/重度占比
- 预警处置率：已处置 vs 待处置

**三、横向对比**
- 同级对比：同级别学校/区县横向排名
- 重点标识：超出正常范围的单元
- 差异分析：显著差异项目说明

**四、趋势分析**
- 年度趋势：本年度 vs 上年度对比
- 学期趋势：本学期 vs 上学期对比
- 变化标识：显著变化趋势说明

### 6.4 报告生成与分发机制

**实时生成（个体报告）：**
- 学生完成测评后自动触发
- 计算得分 → 生成报告 → 存储OSS → 通知用户
- 目标：5分钟内完成

**定时生成（群体报告）：**
- 测评任务结束后触发
- 每日汇总统计 → 更新群体报告
- 支持手动触发即时生成

**报告存储：**
- OSS存储PDF文件
- CDN加速下载
- 文件加密存储（预警报告）
- 保留周期：学生在校期间 + 毕业后3年

## 八、运维保障与实施计划

### 8.1 运维监控体系

**监控维度：**

| 类型 | 监控内容 |
|------|----------|
| 应用监控 | 服务健康状态、请求响应时间、错误率、QPS统计、运行时指标 |
| 资源监控 | CPU、内存、磁盘使用率、网络流量、连接数、Pod/节点状态 |
| 数据库监控 | MySQL连接数、慢查询、Redis命中率、内存使用、ClickHouse查询性能 |
| 业务监控 | 答题完成率、提交成功率、报告生成状态、预警处理率、实时在线人数 |

**告警策略：**

| 级别 | 响应时间 | 告警条件 |
|------|----------|----------|
| P0 紧急 | 立即响应 | 核心服务不可用、数据库宕机、响应时间>5秒持续5分钟 |
| P1 高优先级 | 30分钟内 | 服务错误率>5%、CPU>80%持续10分钟、MySQL慢查询激增 |
| P2 中优先级 | 工作时间 | 内存>70%、磁盘>80%、业务指标异常波动 |

### 8.2 数据备份策略

| 数据类型 | 备份策略 | 备份保留 |

## 九、关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 系统定位 | 筛查预警型 | 重点在于识别需要关注的学生，及时预警干预 |
| 量表方案 | 可配置量表库 | 支持多种量表，管理员可自由组合配置，量表库可扩展 |
| 组织架构 | 五级架构 | 省-市-区县-学校-班级，班主任可查看本班数据 |
| 答题时段 | 分散灵活时段 | 各学校/区县自主安排时间窗口，系统负载相对平滑 |
| 报告维度 | 多维度分析报告 | 基础报告 + 趋势对比、横向对比、预警分析 |
| 技术栈 | 云原生部署 | 阿里云/腾讯云，容器化部署，弹性伸缩 |
| 架构方案 | 云原生微服务 | 弹性伸缩应对峰值，服务隔离容错性好，适合长期演进 |
| 安全合规 | 基础合规 | 符合《个人信息保护法》，数据加密存储传输，访问日志审计 |
| 系统集成 | 独立系统 | 用户数据独立管理，不依赖外部系统 |

## 十、风险与约束

1. **数据敏感性**：学生心理数据属于高敏感信息，需严格权限控制和隐私保护
2. **峰值应对**：3万并发需要充分的容量规划和弹性伸缩能力
3. **报表复杂度**：多维度分析需要ClickHouse等大数据组件支撑
4. **项目周期**：8-11个月周期较长，需要合理的里程碑规划
5. **运维能力**：云原生微服务架构需要团队具备K8s运维能力
